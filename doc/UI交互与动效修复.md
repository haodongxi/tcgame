# UI 交互与动效修复记录

> Created by: haodongsheng

## 1. 本轮问题清单

| 问题 | 根因 | 修复策略 |
| --- | --- | --- |
| 手机需要上下滑才能看到战斗底部 | 战斗页沿用普通页面的最小高度，没有用视口高度锁定内部区域 | 战斗页使用 `100dvh`，日志独立滚动，页面本身不滚动 |
| 手牌偶尔“吐牌”、高度不齐 | 横向 flex 子项没有统一高度，选中缩放与滚动容器共同影响布局 | 手牌区域固定高度，卡牌固定宽高，使用 `align-items: stretch` |
| 每次出牌手牌回到第一张 | `render()` 重建 DOM 后丢失 `.hand.scrollLeft` | 重建前记录横向滚动位置，重建后恢复 |
| 出牌没有反馈 | 出牌逻辑立即修改状态并重绘 | 出牌按钮先进入 `is-playing` 动画，约 220ms 后结算 |
| 发牌没有反馈 | 新抽到的牌与已有牌使用相同渲染路径 | 卡牌按索引使用错峰 `card-deal` 动画 |
| 桌面端和手机端信息密度不稳定 | 同一套纵向布局没有对不同高度做约束 | 手机、平板和桌面分别限制战斗区域与手牌高度 |

## 2. 战斗页一屏布局

战斗页从上到下固定为：

```text
顶部资源栏       auto
敌方信息区       auto
战斗日志区       1fr，可独立滚动
我方状态区       auto
手牌区           固定高度
操作栏           auto
```

页面本身禁止滚动，只有战斗日志和手牌横向区域允许滚动。这样手机竖屏可以完整看到结束回合按钮，桌面端也不会把卡牌拉到页面底部之外。

## 3. 动效规范

- 发牌：卡牌从下方轻微上移并淡入，间隔 45ms。
- 出牌：被点击卡牌上浮、缩小并淡出，结算延迟约 220ms。
- 选中：只改变视觉层级，不改变其他卡牌的布局宽度。
- 动效不承担信息表达；开启 `prefers-reduced-motion` 时全部降级为无动画。
- 出牌动画期间锁定其他出牌操作，避免重复结算。

## 4. 交互验收

1. 375×812 手机视口打开战斗页，不需要页面上下滑动即可看到结束回合。
2. 牌数超过一屏时，左右滑动后打出牌，结算后仍停留在原横向位置附近。
3. 新回合抽牌时卡牌依次出现，不出现重叠、跳位或高度不一致。
4. 连续快速点击同一张牌只结算一次。
5. 电脑宽屏战斗页保持居中，日志区域扩大但不把操作栏推出视口。
6. 系统开启减少动态效果后，牌仍可正常出入手牌并完成结算。

## 5. 本轮不改动

- 不引入音效和音乐。
- 不部署线上环境。
- 不增加微信小程序工程。
- 不改变已有战斗数值和存档格式。

## 6. 追加修复：局部更新与牌面可读性

上一版仍存在三个实现层问题：`.hand` 没有明确禁止纵向溢出；出牌后 `render()` 会重建整个游戏根节点，造成战斗区闪烁；卡牌高度偏紧且标题不换行，导致底部效果文本被裁掉。

本次调整如下：

- 手牌容器增加 `overflow-y: hidden` 与 `touch-action: pan-x`，只保留横向滑动。
- 出牌和结束回合改为只替换敌方信息、日志、玩家状态、手牌四个战斗子区域，不再重建整页；原有横向滚动位置继续保留。
- 发牌动画只在进入新战斗或新回合抽牌时启用，出牌结算不会让旧牌重新播放发牌动画。
- 卡牌标题允许换行；卡牌详情不在牌面文字区展示，后续由卡牌图片承载。

### 追加验收

1. 在手机上上下拖动手牌不会带动手牌容器纵向滚动，左右拖动仍可浏览全部牌。
2. 出牌后敌我状态和手牌即时更新，但战斗页背景、日志容器和页面滚动位置不闪烁、不跳回顶部。
3. 牌名为两行或效果较长时，卡牌底部说明完整可见。

## 7. 截图反馈后的二次修复

根据移动端截图继续修复三个问题：

- 卡牌按钮改为固定尺寸的纵向 flex 容器，牌堆本身保持 `overflow-y: hidden`；卡牌详情从牌面文字和悬停提示中移除，后续由卡牌图片承载。
- 出牌时只移除被打出的卡牌节点，保留其他手牌的 DOM 和横向位置；抽牌导致新增卡牌时只追加新增节点，避免整块手牌闪烁。
- 战斗日志更新后统一将 `scrollTop` 设置为 `scrollHeight`，始终显示最新一条出招消息。
