# 三国肉鸽卡牌 Web MVP 规划与技术方案

> Created by: haodongsheng  
> Version: 0.1  
> Date: 2026-08-19  
> 依据：`doc/策划.md`、`doc/UI.MD`、`img/界面UI.png`、`img/界面UI调整.png`

## 1. MVP 目标

在浏览器中完成一条可重复游玩的最小闭环：

```text
选择主将 → 进入地图 → 选择路线节点 → 回合制卡牌战斗 → 战斗奖励 → 下一节点
                                      ↘ 战败/通关 → 结算 → 永久材料保存
```

MVP 的成功标准不是内容数量，而是玩家能在 10 分钟内理解并完成一次“构筑—战斗—奖励—成长”的循环，并愿意马上开始第二局。

## 2. MVP 范围

### 2.1 必须实现（P0）

| 模块 | MVP 内容 | 验收标准 |
| --- | --- | --- |
| 入口 | 标题页、开始出征、继续游戏 | 刷新页面后能保留永久材料；按钮状态明确 |
| 主将 | 张飞、诸葛亮、赵云三选一 | 三名主将拥有不同核心机制和初始牌组 |
| 地图 | 单章节、5 个节点、线性分支 | 每次战斗后能选择下一节点；节点状态可读 |
| 战斗 | 1 个普通敌人、1 个精英、1 个 Boss | 能完成至少 3 场战斗；敌人意图始终可见 |
| 卡牌 | 通用牌 5 张、每名主将 3 张专属牌 | 抽牌、出牌、弃牌、洗牌、费用校验正确 |
| 回合 | 3 气力、5 张起手、护甲、兵力 | 结束回合后敌方按意图行动，状态更新正确 |
| 奖励 | 战后 3 选 1 张牌；铢钱奖励 | 奖励能影响当前局后续战斗 |
| 结算 | 胜利/失败结算页 | 兵革残片和将校虎符按规则永久保存；局内牌组清空 |
| 存档 | `localStorage` 本地存档 | 关闭/刷新后永久材料和解锁状态不丢失 |
| UI | 竖屏移动端战斗页 | 375px 宽度下无横向溢出，手牌可点选，日志可滚动 |

### 2.2 延后到 MVP 之后（P1/P2）

- 将魂掉落、重复将魂熔铸/凝练、完整羁绊配方
- 商店、事件、迷雾节点、休整节点
- 永久天赋树、铸兵坊、将魂谱完整页面
- 多章节、噩梦难度、每日挑战、隐藏结局
- 联机、账号体系、云存档、埋点后台
- 正式武将立绘和复杂粒子特效

这样可以避免在战斗规则尚未验证前，被内容生产和后端系统拖慢。

## 3. 推荐 Web 技术栈

### 3.1 选择

- **Vite + React + TypeScript**：快速搭建单页游戏，组件状态边界清晰。
- **CSS Modules 或普通 CSS**：MVP 不引入重量级 UI 库，便于实现卷轴、金边、墨色背景等主题样式。
- **Zustand 或 React Context + reducer**：管理战斗状态、地图状态和永久进度。若追求零依赖，首版使用 `useReducer`。
- **Vitest**：测试伤害、费用、抽牌、洗牌、状态效果等纯规则。
- **Playwright**：验证移动端关键流程：开始、出牌、结束回合、战斗结束、刷新恢复。
- **localStorage**：MVP 本地存档；未来可以把存档接口替换成云端 API。
- **PWA**：支持添加到主屏幕和离线运行，先不做微信小程序适配层。

### 3.2 不在 MVP 引入

- 游戏引擎、Canvas/WebGL：当前玩法以文字、卡牌和状态面板为主，DOM 更利于响应式布局和无障碍。
- 后端数据库和登录：不影响第一轮玩法验证。
- 远程图片 CDN：先使用仓库内资源或 CSS 占位图，避免网络加载影响首屏。

## 4. 页面与状态流

```text
TitleScreen
  └─ HeroSelect
       └─ MapScreen
            ├─ BattleScreen
            │    ├─ CardRewardModal
            │    └─ BattleResult
            └─ RunResult
                 └─ TitleScreen / MapScreen
```

### 4.1 页面职责

- **TitleScreen**：展示游戏标题、永久材料、开始/继续按钮。
- **HeroSelect**：展示三名主将的定位、机制和初始牌组摘要。
- **MapScreen**：展示当前章节、已完成节点和可选下一节点。
- **BattleScreen**：集中呈现敌方信息、战斗日志、我方状态、手牌和结束回合按钮。
- **CardRewardModal**：战斗胜利后从三张候选牌中选择一张或跳过。
- **RunResult**：展示本局结果、带回材料和统计信息。

## 5. 战斗 MVP 规则冻结版

### 5.1 玩家回合

1. 回合开始：气力恢复为 3，护甲清零，抽 5 张牌。
2. 玩家打出手牌：消耗费用，执行卡牌效果；费用不足时不可打出。
3. 玩家点击“结束回合”：未保留手牌进入弃牌堆。
4. 敌方执行已展示的意图。
5. 进入下一回合。

### 5.2 初始牌组

每名主将 10 张：

- 通用：挺矛直刺 ×2、列阵防御 ×2、厉兵秣马 ×1、干粮 ×1、横扫千军 ×1
- 主将专属：三张专属牌各 1 张

为控制首版复杂度，MVP 先实现张飞完整机制；诸葛亮和赵云先接入不同牌组与简单机制，第二轮再补齐完整状态链。

### 5.3 MVP 卡牌效果

| 卡牌 | 费用 | 效果 |
| --- | ---: | --- |
| 挺矛直刺 | 1 | 造成 55 伤害 |
| 列阵防御 | 1 | 获得 40 护甲 |
| 厉兵秣马 | 1 | 抽 2 张牌 |
| 干粮 | 0 | 回复 30 兵力，不超过上限 |
| 横扫千军 | 2 | 造成 80 伤害 |
| 咆哮突进 | 1 | 造成 60 伤害，获得 2 层狂怒 |
| 据水断桥 | 2 | 获得 50 护甲；每消耗 3 层狂怒额外获得 10 护甲 |
| 燕人咆哮 | 3 | 造成 220 伤害；每层狂怒追加 12 伤害并清空狂怒 |

### 5.4 敌人

| 敌人 | 兵力 | 意图 |
| --- | ---: | --- |
| 黄巾校尉 | 260 | 攻击 35 / 防御 20 轮换 |
| 虎牢守将 | 520 | 攻击 55；每 3 回合强化一次 |
| 董卓亲军 | 900 | 攻击 75 / 防御 45；兵力低于 50% 后攻击 +20 |

所有敌人必须在界面上显示“下回合意图”和数值；随机数使用本局 seed，便于复现问题和编写测试。

## 6. 数据模型建议

```ts
type CardType = 'attack' | 'skill' | 'power' | 'item'

type CardDefinition = {
  id: string
  name: string
  cost: number
  type: CardType
  description: string
  tags?: string[]
}

type Combatant = {
  id: string
  name: string
  hp: number
  maxHp: number
  block: number
  buffs: Record<string, number>
  intent?: Intent
}

type RunState = {
  seed: string
  heroId: string
  nodeIndex: number
  deck: string[]
  drawPile: string[]
  hand: string[]
  discardPile: string[]
  energy: number
  player: Combatant
  enemy?: Combatant
  logs: BattleLog[]
  rewards: RunReward
}

type MetaProgress = {
  shards: number
  commandTalisman: number
  unlockedHeroes: string[]
  version: number
}
```

规则层必须是纯函数或尽量无副作用，UI 只派发动作：

```text
PLAY_CARD → END_TURN → ENEMY_ACT → START_TURN → DRAW_CARDS
```

这样可以直接测试规则，也便于未来接入动画、回放和云存档。

## 7. UI 实现要点

### 7.1 视觉基线

- 背景：墨黑 `#171612`，叠加米色半透明战场层。
- 面板：宣纸色 `#f2ead7`，深墨边框，暗金装饰线。
- 强调：朱砂红 `#a43a2a`；可用操作使用金色，禁用操作降低对比度。
- 字体：优先系统中文字体，标题使用更有书卷感的衬线字体；不依赖外部字体下载。

### 7.2 战斗页布局

沿用 `doc/UI.MD` 的四层结构：敌方信息约 22%、战斗日志约 33%、我方状态约 15%、手牌约 30%。实现时使用 `min-height: 100dvh` 和 CSS Grid/Flex，不把高度写死为 750px。

- 手牌横向滚动，卡牌至少 68px 宽、点击区域至少 44px。
- 点击卡牌后提升 z-index 并显示完整描述；再次点击或点击空白区域取消选择。
- “结束回合”固定在拇指可触达的右下区域，必须有 disabled 和 loading 状态。
- 日志自动滚动到底部，但用户查看历史时暂时不抢回滚动位置。
- 所有重要数字同时使用颜色和文字表达，不能只依靠颜色区分。

参考图中的武将头像和战场图可作为视觉参考；MVP 未有正式授权资产时，应使用仓库内素材或 CSS/渐变占位，不把 AI 生成图直接当作最终版权资产。

## 9. 开发拆分与完成定义

### Sprint 1：规则可玩

- 初始化 Vite、React、TypeScript、测试工具。
- 完成牌库、抽牌、弃牌、洗牌、费用、伤害、护甲和敌方意图。
- 用纯文本界面跑通一场战斗。

**完成定义**：规则测试通过，能稳定完成胜利和失败两种结果。

### Sprint 2：竖屏战斗 UI

- 按参考图完成战斗页四层布局。
- 接入手牌选择、卡牌放大、日志滚动、结束回合。
- 加入响应式和键盘可操作性。

**完成定义**：375×812、390×844 两个视口无横向溢出；移动端点击路径完整。

### Sprint 3：地图与局内闭环

- 加入主将选择、5 节点地图、战后奖励、三场战斗。
- 接入胜负结算，清空局内状态，保留永久材料。

**完成定义**：新玩家无需开发者工具即可从打开网页玩到结算。

### Sprint 4：存档与打磨

- 加入 `localStorage` 版本化存档和异常恢复。
- 增加音效开关、重新开始确认、规则提示、空状态和错误状态。
- 用 Playwright 做一条端到端冒烟测试。

**完成定义**：刷新页面后可继续；存档版本变化不会让页面白屏；核心流程无阻断错误。

## 10. 测试与验收清单

- 卡牌费用永远不会变成负数。
- 伤害先扣护甲，再扣兵力；护甲不会出现负数。
- 牌库为空时正确洗入弃牌堆；所有牌都在某个牌堆或手牌中，不重复丢失。
- 抽牌超过手牌上限时按规则处理。
- 张飞兵力低于 50% 时狂怒触发逻辑正确。
- 敌方意图与实际行动一致。
- 战斗结束后不能继续出牌或结束回合。
- 结算后局内牌组、铢钱、将魂不污染下一局。
- 永久材料刷新后仍存在。
- 375px 宽屏下按钮、卡牌、日志均可操作。
- `prefers-reduced-motion` 开启时不依赖动画表达状态变化。

## 11. 风险与决策

1. **内容过大**：先只实现一条章节和张飞完整机制，诸葛亮/赵云先保留入口和基础差异。
2. **UI 过度追求美术**：先用 CSS token 和占位图验证信息层级，正式美术资产后置。
3. **规则难以调试**：所有随机行为绑定 seed，战斗日志记录动作和结果。
4. **移动端空间不足**：优先确保兵力、意图、费用和结束回合可读，次要状态折叠。
5. **未来平台迁移**：业务规则不依赖浏览器 API，存档和输入层隔离，后续可迁移到小程序。

## 12. MVP 之后的演进顺序

1. 补齐三名主将的核心机制和专属牌。
2. 加入将魂、重复处理和 3~5 个高价值羁绊。
3. 加入商店、事件、精英节点和休整节点。
4. 加入韬略阁的 6~8 个永久天赋。
5. 扩展章节、Boss 和正式美术资源。
6. 最后评估云存档、账号、数据分析和微信小程序封装。
