## 1. 本轮目标

把 MVP7 规划中的三章路线从“第一章路线骨架”推进为可连续游玩的章节流程，并修复卡牌图片在本地静态服务器和 GitHub Pages 下不显示的问题。

本轮范围：

1. 第一章 15 层、第二章 17 层、第三章 19 层路线可连续推进。
2. 每章路线显示当前章节、层数和节点类型；章节 Boss 胜利后进入下一章。
3. 第二、三章接入对应主题的普通战、精英战和 Boss 敌人组。
4. 章节 Boss 战利品保留现有奖励流程，为后续传说牌和军械双奖励预留接口。
5. 统一卡牌资源路径，兼容直接打开 `web/index.html`、本地静态服务器和 GitHub Pages。

## 2. 路线状态

```text
state.chapter  当前章节，0~2
state.node     当前章节层数
chapterRouteColumns[chapter]  当前章节路线节点
```

章节结束后：

- 第一章 Boss 胜利：进入第二章第 0 层。
- 第二章 Boss 胜利：进入第三章第 0 层。
- 第三章 Boss 胜利：结算整局奖励并清理行军存档。

旧存档没有 `chapter` 字段时按第一章加载，不影响已有存档继续游玩。

## 4. 卡牌图片资源规范

当前项目是无构建工具的静态 Web：`web/index.html` 直接加载 `web/src/app.js`，因此浏览器会以页面 URL 为基准解析图片地址。图片实际位于：

```text
web/public/assets/cards/base/
web/public/assets/cards/zhangfei/
```

所以卡牌数据必须使用 `./public/assets/cards/...`。CSS 背景位于 `web/src/styles.css`，相对 CSS 文件使用 `../public/assets/...`。

禁止混用 `./assets/...`，否则会请求不存在的 `web/assets/...`，表现为卡牌区域出现破损图片图标和 `alt` 文本。

## 5. 验收标准

1. 新开一局可以从第一章进入第二章，再进入第三章，不会因 Boss 节点提前结算。
2. 第二章至少能看到西凉军敌人，第三章至少能看到曹军或陷阵营敌人。
3. 三章层数分别为 15、17、19 层，章节标题和进度正确显示。
4. 本地打开 `web/index.html` 或访问本地静态服务器时，基础牌和张飞 18 张专属牌均能显示图片。
5. GitHub Pages 以 `web` 为发布目录时，图片请求路径不再落到不存在的 `assets` 目录。
6. `node --check web/src/app.js` 和 `git diff --check` 通过。
